# AI Coding Arena — AI 编程助手横向评测

用**同一条指令、同一个场景**，分别交给多款 AI 编程助手独立实现，然后把生成结果原样嵌进同一个页面里**直接可玩、可对比**，帮助团队与管理层直观判断该选用哪款 AI 工具。

已参评 4 款：**Kiro**（AWS）、**GitHub Copilot**（GitHub）、**Antigravity**（Google）、**Codex**（OpenAI）。两个场景阵容一致，总分可直接比较。

🔗 **在线体验**：<https://cf3901646.github.io/ai-coding-arena/>

纯静态网站，无需后端，所有 Demo 均可在浏览器里直接运行。

## 场景一：简单赛车游戏 — 评测结论

**提示词**：帮我做一个运行在 HTML 上的大世界开车游戏，你自己构想细节，要求是用 WASD 操作车辆，游戏要好玩。不要问我任何细节，所有的你自己想，自己验证，可行后交付给我。

提示词里有四条可核对的硬要求：**大世界**、**WASD 操控**、**好玩**、**自己验证后再交付**。评分按这四条逐一实测。

| 排名 | AI | 厂商 | 综合总分 | 耗时 | 一句话点评 |
|---|---|---|---|---|---|
| 1 | **Kiro** | AWS | **52 / 60** | 35 分钟 | 唯一四条硬要求全达标：无缝大地图 + 完整任务循环，操控流畅无 bug |
| 2 | **GitHub Copilot** | GitHub | 35 / 60 | 15 分钟 | 世界规模最大、操控流畅，但中文输入法下 WASD 完全失效 |
| 3 | **Antigravity** | Google | 27 / 60 | 1 分钟 | 3D 画面花哨，但没有玩法引导，操控有 bug；出图最快 |
| 4 | **Codex** | OpenAI | 20 / 60 | 15 分钟 | 任务与指示都写了，但画面最简陋、加速迟滞得几乎开不动 |

**关键实测：WASD 的中文输入法兼容性**

提示词点名要用 WASD，因此专门测了输入法激活时（浏览器把 `e.key` 置为 `Process`）能否继续驾驶：

| AI | 键盘取值方式 | 正常按 W | 输入法激活时 | 结果 |
|---|---|---|---|---|
| Kiro | `e.code` | 199 km/h | 204 km/h | ✅ 正常 |
| Antigravity | `e.code` | 42 km/h | 66 km/h | ✅ 正常 |
| Codex | `e.code` | 14 km/h | 15 km/h | ✅ 正常（但本身就开不快） |
| GitHub Copilot | 仅 `e.key.toLowerCase()` | 298 km/h | **0 km/h** | ❌ 完全失效 |

这是 Copilot 指令遵循分被扣的主因：在中文办公环境里，只要输入法处于中文态，整个游戏就无法操作——而这恰恰是提示词唯一点名的操作方式，也说明它的「自己验证」没有覆盖真实使用场景。

> 结论：四个模型都能在一次对话内产出可运行的单文件 HTML，差距不在「能不能跑」，而在「是不是一个成品」。
> 提示词明确要求「自己验证，可行后交付」，但只有 Kiro 交付了没有操控缺陷的版本。
> 对交付质量敏感的场景推荐 Kiro；对迭代速度敏感的日常编码推荐 GitHub Copilot。

完整的分维度数据和雷达图见网站首页与 [赛车游戏详情页](scenarios/racing-game.html)。

## 场景二：飞利浦编年史页面 — 评测结论

**提示词**：给飞利浦这家公司设计一个简单的编年史 HTML 页面，简单诉说飞利浦公司的历史，重点且详细展示当前公司的转型和业务，以及公司产品、未来愿景等内容。具体怎么做你自己决定，但要高级流畅，展现大公司的历史和对人类的贡献。

| 排名 | AI | 综合总分 | 耗时 | 一句话点评 |
|---|---|---|---|---|
| 1 | **Kiro** | **54 / 60** | 33.5 分钟 | 叙事最完整、数据经核查全部属实，唯一实现无障碍降级；但暗色主题不符合企业品牌规范 |
| 2 | **GitHub Copilot** | 49 / 60 | 6 分钟 | 结构工整、32KB 零依赖加载最快、零缺陷，亮色调对味但视觉缺少记忆点 |
| 3= | **Antigravity** | 42 / 60 | **1 分钟** | 配色观感最舒服、唯一有可用交互，但内容最薄且手机/平板均横向溢出 |
| 3= | **Codex** | 42 / 60 | 15 分钟 | **画面最好看**、唯一用真实实拍图，但正文配色失效、内容最少 |

评测结合两类依据：**客观实测**用真实浏览器（Playwright + Chromium）渲染后量化测量；**主观判断**由评估者实际浏览后给出（视觉观感、叙事质量）。

| 实测项 | Codex | Antigravity | Copilot | Kiro |
|---|---|---|---|---|
| 正文中文字数 | 1428 | 2266 | 2503 | **4709** |
| 年份节点数 | 11 | 7 | 17 | **36** |
| 数值断言数 | 35 | 3 | 33 | **95** |
| 真实配图 | **7 张** | 0 | 0 | 0 |
| 加载耗时 / 体积 | 254ms / 844KB | 654ms / 132KB | **163ms / 32KB** | 522ms / 80KB |
| 滚动帧率 | 61fps | 61fps | 60fps | 60fps |
| 移动端 390px 溢出 | 无 | **26px** | 无 | 无 |
| 平板 768px 溢出 | 无 | **26px** | 无 | 无 |
| 中文标题行高塌陷 | **2 处** | 无 | 无 | 无 |
| 页面底色亮度 | 深蓝区块 | 250（亮） | 248（亮） | **7（近纯黑）** |
| 减少动效模式降级 | ✅ | ❌ | ❌ | **✅** |
| 锚点导航死链 | 0 | 0 | 0 | 0 |
| JS 报错 | 0 | 0 | 0 | 0 |

**四个关键发现：**

1. **Codex 的产物混进了终端输出。** HTML 第 10–12 行出现了 `Exit code: 0` / `Wall time: 0.3 seconds` / `Output:`。CSS 解析器在顶层遇到 `Exit` 会把它当选择器起始，一路吞到下一个 `{`，导致紧随其后的整个 `:root` 变量块失效——7 个颜色变量全部为空。**实测影响集中在正文区**：米色底 `#f4f2ec` 变纯白、品牌蓝数字变黑、12 处标签卡片失去底色与描边；首屏因为大图叠深蓝遮罩，几乎看不出差别，所以肉眼很容易漏掉。站内提供了**修复版切换开关**（仅删除那 44 个字符，其余代码一字未改），可直接对照。
   另有一处**独立缺陷**：两处大标题中文行高小于字号（108px 字号配 97px 行高），汉字上下相撞。此问题在修复版里依然存在，与终端输出无关。

2. **Kiro 的数据经核查全部属实，含一个五周前才获批的新品。** €17.8B 营收、可比增长 2%、**Q4 单季 +7%** 与官方财报一致，BlueSeal / Azurion / Zenition / Rembra / SmartIQ 均为真实在售产品，并附了数据来源清单。其中超声平台 **「Alturion」** 初次核查因公开报道极少一度被误判为虚构，后经 **FDA 510(k) 数据库**核实确认真实存在——受理号 **K260667**，申请人 Philips Ultrasound, LLC（Bothell, WA），**2026 年 6 月 29 日获批**，距本次评测仅五周。四份产出里只有 Kiro 引用到了这个级别的最新产品信息。Copilot 的「约 7 万员工」与 2024 年报的 68,419 略有出入。

3. **Antigravity 与 Codex 同为 42 分并列，但强弱完全互补。** Antigravity 赢在文字量（2266 vs 1428 字）、唯一可用交互、零渲染缺陷；Codex 赢在视觉（10 vs 8）与实拍配图。两者共同的短板是内容深度——年份节点 7 / 11 个，而 Kiro 有 36 个。

4. **Kiro 的暗色主题是企业场景里的实际减分项。** 实测页面底色为 `rgb(5,7,13)`（亮度 7，近纯黑），是四份中唯一的暗色主题——Copilot 与 Antigravity 分别为 248 和 250。暗色科技风本身完成度不低，但飞利浦对外品牌体系以白底 + 品牌蓝为主，官网、年报、产品页均为亮色调。这份产出若直接用于对外场景需要整体重做配色，属于实打实的返工成本，因此视觉一项从 9 分下调至 7 分，与 Copilot 持平——但两者失分原因相反：Copilot 是「对味但平庸」，Kiro 是「出彩但跑偏」。

完整数据见 [编年史详情页](scenarios/philips-chronicle.html)。

## 评分维度说明

每项 0–10 分。两场均按提示词原文的硬要求逐条核对。赛车场景结合评估者人工体验与真实浏览器实测（WASD 键盘兼容性、世界规模、任务系统）；编年史场景用真实浏览器量化测量（内容密度、渲染缺陷、无障碍、响应式、性能、主题亮度）并对财务与产品数据做独立事实核查，减少主观漂移。

| 维度 | 说明 |
|---|---|
| 功能完整度 | 是否真的做出了一个能玩／能用的完整产物 |
| 代码质量 | 结构、可读性、可维护性，是否便于二次开发 |
| 视觉/UI设计 | 画面表现力与界面细节打磨程度 |
| 性能/流畅度 | 运行帧率、响应速度、有无卡顿与崩溃 |
| 一次成型度 | 首次输出即可用的程度，需要多少次返工 |
| 指令还原度 | 是否准确理解并实现了需求本意 |

## 维护说明（给后续更新的人）

1. 把新场景 / 新 AI 的代码放进 `demos/<ai-id>/<scenario-id>/index.html`
2. 打开 `assets/js/scores-data.js` 填分数、耗时、点评、`pros` / `cons` 标签
3. 保存后首页雷达图、排名表、场景对比页会**自动同步**，无需改动任何 HTML
   （某个场景的分数全为 0 时，该场景页会自动显示「评测进行中」空状态）

> 提示：如果某个 Demo 依赖外部 CDN（例如 Antigravity 版本依赖 Three.js CDN），需要联网才能看到完整效果，已在对应卡片的说明中注明。
